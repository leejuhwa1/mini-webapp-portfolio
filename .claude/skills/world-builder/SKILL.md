# World Builder

목표: 메인 대화의 컨텍스트를 작게 유지한다. 무거운 작업(기획서 작성, 코드 작성, 검수)은 서브에이전트에게 맡기고, 메인 대화에는 **요약만** 남긴다.

## 새 세계 만들기: Plan → 확인 → Build → Review → 보고

### 0. 입력 확인 (메인)
- 세계 주제가 없으면 사용자에게 묻는다. 직접 고르지 않는다.
- slug를 정한다. 영문 소문자와 하이픈만 쓴다. 예: `rainy-cafe`
- 번호는 `worlds/` 안의 기존 폴더 수 + 1이다. 예: WORLD #002

### 1. Plan (서브에이전트)
Agent 도구(general-purpose)를 이렇게 호출한다.
> `instructions/plan-world.md`를 읽고 따라라. 주제: {주제}, slug: {slug}, 번호: {번호}. 사용자 메모: {사용자가 말한 키워드/분위기 그대로}

결과물은 `worlds/{slug}/plan.md`이다. 서브에이전트는 10줄 이내 요약만 돌려준다.

### 2. 사용자 확인 (메인)
- plan 요약을 사용자에게 보여준다. 공간 구성, 클릭 요소, 소리, 숨겨진 요소를 담는다.
- **사용자가 OK하기 전에는 Build로 넘어가지 않는다.** 수정 요청이 오면 `plan.md`를 직접 고치거나 Plan을 다시 돌린다.

### 3. Build (서브에이전트)
> `instructions/build-world.md`를 읽고 따라라. 대상: `worlds/{slug}/`

서브에이전트는 만든 파일 목록과 확인 방법만 돌려준다.

### 4. Review (서브에이전트)
> `instructions/review-world.md`를 읽고 따라라. 대상: `worlds/{slug}/`

- 결과물은 `worlds/{slug}/review.md`이다.
- 치명 문제가 있으면 Build 서브에이전트에게 review.md를 주고 수정시킨다. 최대 2회까지 하고, 그래도 남으면 사용자에게 보고한다.

### 5. 보고 (메인)
- 사용자에게 무엇이 생겼는지, 어떻게 열어보는지, 알려진 한계를 짧게 말한다.
- 미리보기를 제안한다. 브라우저 창에서 `worlds/{slug}/index.html`을 모바일 크기로 연다.
- 커밋은 사용자가 요청할 때만 한다.

## 기존 세계 수정
- 작은 수정(색, 문구, 위치, 소리 크기 등)은 메인에서 바로 고친다.
- 큰 수정(새 방 추가, 상호작용 구조 변경)은 `plan.md`를 먼저 고친 다음 Build → Review 서브에이전트로 처리한다.
- 수정 전에 커밋되지 않은 중요한 변경이 있으면 "먼저 커밋할까요?"라고 묻는다. 되돌릴 수 있게 하기 위해서다.

## 이미지와 소리 리소스
- 사용자가 준 AI 이미지나 소리 파일이 있으면 `worlds/{slug}/assets/`에 넣어 쓴다.
- 없으면 CSS/SVG/Canvas로 그리고, Web Audio API로 소리를 합성한다. 출처가 불분명한 외부 파일은 내려받지 않는다.
- 사용자가 리소스를 직접 줄 수 있는지는 Plan 단계에서 물어본다.
